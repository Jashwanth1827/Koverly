### 1. Extraction review workflow

An upload used to require an already-linked policy before Submit would work;
documents uploaded straight from the vault had no policy, so confirming
failed. The confirm API was extended to create a policy from the reviewed
fields.

**Backend**

- `backend/app/schemas/document.py`
  - `ExtractionConfirm` gained `create_policy: bool = False` and
    `policy_type: PolicyType | None`; imports `PolicyType`.
- `backend/app/services/extraction_service.py`
  - Added `_infer_policy_type(...)` (best-effort classification, falls back to
    `other`) and `_create_policy_from_confirmed(...)`.
  - Confirm flow can create or match a policy, sets `row.policy_id`, treats
    empty confirmed values as rejected, and records `created_policy` in audit
    metadata.
  - Dedupe: a policy with the same policy number **and** insurer (case
    insensitive) is reused instead of creating a duplicate.
  - `_create_policy_from_confirmed` returns `(policy, created: bool)` so the
    caller knows whether it created or matched.

**Frontend**

- `frontend/src/api/endpoints.ts`
  - Added `documentApi.get(familyId, id)`.
  - `documentApi.confirm` body type extended with `create_policy` and
    `policy_type`.
- `frontend/src/pages/DocumentsPage.tsx` — largely rewritten
  - Upload auto-opens `ExtractionModal`.
  - Modal polls `documentApi.get`, loads extractions, and has three phases:
    `scanning`, `failed`, `review`.
  - Review supports Edit → Save changes / Cancel edits, and Submit.
  - Destination choice: create a new policy vs. add to an existing one, with
    policy-type auto-detect.
  - Submit guard when no field has a value; success notice links to the
    created/updated policy.
  - Removed a nonsensical `configLine(...)` helper that had been left behind.

### 2. OCR and HDFC PDF extraction fixes

**OCR (earlier work, verified today)**

- `backend/app/utils/ocr.py` — lazy RapidOCR, image validation/orientation,
  confidence filtering. Offline, CPU-only.
- `backend/app/utils/text_extract.py` — scanned PDF pages rasterised and OCR'd
  when embedded text is too short; JPG/PNG read directly.
- `backend/app/services/processing_service.py` — extraction offloaded via
  `asyncio.to_thread`.
- `/api/v1/config` reports `ocr_backend` and `ocr_available`.

**HDFC-style PDF fix** — `backend/app/ai/null_provider.py`

The real HDFC policy schedule exposed three problems:

- Values placed on the line **below** their label.
- Mixed-case insurer names (`HDFC ERGO General Insurance Company Limited`).
- Labels like `Total Sum Insured (`)`, `Gross Premium`, `Nominee Details`,
  `Policy Holder's State Name`.

Changes:

- All field patterns are line-anchored (`(?im)^`) and tolerate the value on
  the next line and separators `:`, `.`, `-`.
- Insurer fallback `_COMPANY_NAME` matches mixed-case names (the token class
  was accidentally ALL-CAPS only).
- Label-aware preferences: `policyholder_name` ignores `State Name`,
  `nominee` ignores `Nominee Details`, `sum_insured` prefers
  `Total Sum Insured`, `premium` prefers `Gross Premium`.
- Verified on the real HDFC policy PDF (values redacted in this log):
  `policy_number`, `insurer` (HDFC ERGO General Insurance Company Limited),
  `policyholder_name`, `sum_insured`, `premium`, `start_date`, `expiry_date`,
  and `nominee` were all extracted correctly.

### 3. Multi-format uploads

The vault now extracts from PDF, JPG/PNG, DOCX, XLSX/XLS, CSV, MD, and TXT.

**Dependencies added** (`backend/pyproject.toml`, installed into `.venv`)

- `python-docx>=1.1.0`
- `openpyxl>=3.1.0`
- `xlrd>=2.0.1`

**Text extraction** — `backend/app/utils/text_extract.py`

- `extract_docx_text` — paragraphs plus table rows (cells joined with ` | `).
- `extract_spreadsheet_text` — every sheet, one sheet per page; XLSX via
  `openpyxl` (read-only), XLS via `xlrd`.
- `extract_csv_text`, `extract_plain_text` (MD/TXT), with encoding fallbacks
  (utf-8-sig, utf-16, cp1252, latin-1).
- `extract_text` dispatches by content type and raises a clear
  `TextExtractionError` for unsupported types.

**Content sniffing** — `backend/app/integrations/storage.py`

- `sniff_content_type` now recognises:
  - `%PDF-` → PDF
  - JPEG / PNG magic bytes
  - OLE2 (`D0 CF 11 E0 ...`) → legacy Excel (`.xls`)
  - `PK\x03\x04` ZIP container → OOXML; Word vs Excel disambiguated by the
    declared content type
  - Text formats (`text/markdown`, `text/csv`, `text/plain`) only when the
    payload actually looks like text (`_looks_like_text`), so binaries renamed
    to `.txt` are rejected.

**Config** — `backend/app/core/config.py`, `backend/.env`, `backend/.env.example`

- `ALLOWED_UPLOAD_TYPES` widened to all supported types.
- `document_service.py` error message updated:
  "Unsupported file type. Allowed types: PDF, JPG, PNG, DOCX, XLSX/XLS, CSV, MD, TXT."

**Extraction hardening** — `backend/app/ai/null_provider.py`

- Added `_clean_layout(...)`: strips Markdown emphasis/headings, list bullets,
  table pipes and CSV commas (first separator becomes `:`), and parenthetical
  label qualifiers (`Premium (in INR):`, `Sum Assured (Rs.):`).
- Insurer fallback extended with `_COMPANY_CORPORATION` for
  `... Insurance Corporation of <Country>` (e.g. `LIFE INSURANCE CORPORATION
  OF INDIA`, all-caps or mixed case).
- Date labels added: `Date of Commencement`, `Date of Maturity`,
  `Risk Commencement Date`.

**Frontend**

- `frontend/src/lib/format.ts` — exports `ACCEPTED_UPLOAD_TYPES` and
  `ACCEPTED_FORMATS_LABEL`, kept in sync with the backend setting.
- `DocumentsPage.tsx`, `OnboardingPage.tsx`, `ClaimDetailPage.tsx` — use the
  shared accept string; updated copy lists the new formats.
- `README.md` — Documents and AI extraction rows updated.

### Known issues / follow-ups

- Real insurer PDFs were **not** tested; the LIC/SBI/IDBI checks used
  hand-written samples. Extraction works broadly but is not guaranteed for
  unseen layouts.
- Legacy `.doc` (OLE2 ops) is routed to the Excel reader; true `.doc` would
  need its own parser.
- Only JPG/PNG images supported (no WEBP/TIFF yet).
- `frontend/src/components/Modal.tsx` close glyph renders as a box in some
  fonts; not fixed.
- `policy_service.create_policy` commits internally, so a later confirmation
  failure could leave a partially-created policy (acceptable for now).
