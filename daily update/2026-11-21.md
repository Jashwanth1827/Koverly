## Session 4 — 01:48 (commit `17c8380`)

“Fix premature error while document analysis is still starting.”

### Root cause of “Upload policy document → Something went wrong.”

The upload itself succeeded (so the document appeared under Documents), but the
form immediately polled `/analysis`. Background processing had not created the
analysis row yet, so the first poll returned:

    404 {"error":{"code":"NOT_FOUND","message":"This document has not been analysed yet.", ...}}

The form treated that normal “still processing” state as fatal and displayed
`Something went wrong.`.

### Changes

- `backend/app/services/candidate_service.py` — `get_analysis()` returns
  `(None, [])` when the analysis row does not exist yet, instead of raising
  `NotFoundError`. A comment explains that this is the normal async-processing
  state.
- `backend/app/api/v1/documents.py` — serializes `analysis=None` safely in
  `AnalysisDetailOut`.
- `frontend/src/components/UploadPolicyForm.tsx` — treats transient `404`,
  network (`0`) and `5xx` responses during polling as retryable rather than
  fatal.
- `backend/tests/test_understanding.py` — added
  `test_analysis_is_empty_while_document_is_still_processing`, which
  monkeypatches `process_document` to a no-op and asserts the analysis endpoint
  returns `200 {"analysis": null, "candidates": [], "candidate_count": 0}`.

### Verification

Reproduced the original 404 first. After the fix, the browser network log
showed two successful polls:

1. `200` — empty analysis, still processing
2. `200` — full analysis

The form then showed **“We found your policy”** with the extracted insurer,
policy number and other fields. No console errors.

## Session 5 — 01:58 (commit `156845f`)

“Wait for slow document processing instead of reporting a timeout.”

The user then saw **“This is taking longer than expected. You can retry, or add
the policy manually.”** That was the old 20-attempt × 3-second (60-second)
fallback. The backend permits up to 10 OCR pages at up to 60 seconds each, so
60 seconds is far too short for a scanned document.

### Changes

- `frontend/src/components/UploadPolicyForm.tsx`
  - Added `POLL_INTERVAL_MS = 3000` and `MAX_POLL_ATTEMPTS = 240` (~12 minutes).
  - Added `timedOut` state. The timeout branch now says the document is saved
    and offers **Keep waiting** / **Check later** instead of framing it as a
    failure.
  - `reset()` clears any pending poll timer; `continueWaiting()` restarts
    polling from the same document.
- `frontend/src/pages/DocumentsPage.tsx`
  - Replaced the 15 × 700 ms list-based poll (~10 seconds) with a 240 × 3000 ms
    poll against `documentApi.get`.
  - Transient `404` / network / `5xx` errors are ignored while waiting.
  - If it still has not finished, the message now says the document is saved
    and can be reopened from the Documents page in a few minutes.
